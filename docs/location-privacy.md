用户在 iPhone 上已允许使用期间定位，但小程序显示隐私授权相关的“定位暂不可用”。旧版把所有包含 privacy 的接口错误归为同一条提示，无法仅凭该截图判断后台指引是否缺失、用户是否拒绝或接口是否未声明。

用户随后明确确认：当前 AppID 尚未在微信公众平台配置隐私保护指引。这是已确认的后台缺项，需账号持有人配置并提交；完成前不能认为代码修复即可恢复定位。

后续用户报告隐私配置已完成，新截图显示“位置用途或接口权限尚未配置完成”。该提示仍合并了用途未声明与接口准入两种情况，不能只凭截图断言是哪一个接口失败。下一步检查公众平台接口设置中的实际开通状态。

代码检查发现没有实现 `wx.onNeedPrivacyAuthorization` 配套弹窗和官方同意按钮。已补齐隐私授权代理及附近、发布、对话页的授权组件；只有用户点击 `open-type="agreePrivacyAuthorization"` 按钮后，才使用微信的 resolve 回调继续请求。不同意可保留演示体验，下一次进入真实定位可重试；没有用本地布尔值冒充同意。

附近页弹窗出现时暂时卸载地图和 cover-view，避免原生地图层挡住同意按钮。已区分隐私授权、明确的接口声明/准入错误、定位权限拒绝、系统定位关闭及持续定位失败；隐私错误不再一律跳转位置设置。

本次未运行自动化测试或真机测试，也未代用户同意隐私协议。修复后的手机定位结果仍需用户确认。

## 仍需在账号及设备确认

1. 微信公众平台当前小程序 AppID 应为 `wx755951e5f06c6cea`。
2. 找到《小程序用户隐私保护指引》，按实际功能声明位置信息及现场拍摄/用户选择图片的用途，提交并确认有效。不能仅在 `app.json` 写用途就代替后台配置；联系人等内容由账号持有人填写。
3. 确认当前账号对 `getLocation`、`startLocationUpdate` 等接口的实际权限与类目要求。声明接口并不等于自动获准。
4. 在开发者工具完整编译并重新生成“预览”二维码，手机退出旧预览后扫码打开新代码。此次仅涉及客户端，无需重新部署云函数。
5. 选择真实定位，阅读微信展示的隐私保护指引，由用户点击“同意并继续”。随后允许小程序位置权限；iPhone 系统还需允许微信使用期间访问位置，并启用准确位置。
6. 若仍失败，提供新版提示。通过真机调试可进一步查看失败 API 的 `errMsg` / `errCode`；不要打印坐标、邀请码或内部身份凭据。

## 定位接口权限申请

公众平台 → 开发 → 开发管理 → 接口设置 → 地理位置，查看 `getLocation`、`startLocationUpdate`、`onLocationChange` 的可申请范围和状态。当前代码只使用前台定位，未使用 `startLocationUpdateBackground`。代码中的三个位置接口声明已存在；后台是否获准仍需账号页面确认。

申请说明应如实填写，例如：“留答提供与实际地点绑定的留话和现场回复。用户主动开启真实定位时，获取当前位置以展示附近留话、计算与留言点的距离，并校验是否到场；前台位置变化用于更新地图和距离，离开页面或小程序进入后台时停止持续定位。” 此说明对应现有实现，不代表一定满足平台准入类目。

接口受主体与服务类目限制，单次定位和持续定位的开放类目可能不同。若后台提示类目不支持，保留原始提示，按实际业务与资质评估；不通过修改代码或填报不实用途绕过。若全部显示已开通，转查失败 API 原始错误与生效的隐私声明，避免重复申请。

参考：微信官方 [API 类型声明及隐私接口示例](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)、[隐私授权开发文档](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。本次官方文档网页无法打开，已直接读取官方类型声明中的接口说明与示例。
