# 整校夜游底图与 GPS 接入

日期：2026-10-27。对应 Issue #8。当前是覆盖整校范围的可运行初版，开放数据缺少的建筑尚未补全，不代表完成了逐栋三维建模或实地配准。

## 在小程序里打开

1. 微信开发者工具导入仓库根目录，重新编译。
2. 附近页右上角「…」→「地图与场景」→「贸大夜游地图」。演示模式也可从这个入口切换到真实定位模式。
3. 手机完成原有定位/隐私授权。在校园边界内取得位置后，蓝点跟随 GPS；拖动地图会暂停跟随，点回位按钮恢复。
4. 「…」→「地图缩放」支持放大、缩小与查看整校；画面支持双指缩放。附近列表、真实留言卡片、现场发布入口、点赞与接话继续走现有流程。
5. 在校园外可浏览整校，点击「回到我」返回标准地图；也可在「地图与场景」中手动选择标准地图。

未得到定位时可以先浏览校园，界面提示开启定位。图片加载失败时提示切换标准地图。底图来源与精度说明可点击右下角署名查看。没有新增 AppID、地图 Key、位置权限或云函数部署步骤。

## 接入内容

| 层 | 实现与范围 |
| --- | --- |
| 底图 | 67 个已有开放几何对象；全校范围图片 1536×1845，JPEG 434601 bytes。东北片区以条纹和“建筑待补绘”注明资料缺口。 |
| 坐标 | 构建时将 WGS84 参考几何近似转换为 GCJ-02，再按客户端相同的局部米制投影绘图；GPS、留言与地图相机使用同一个原点。 |
| 显示 | 一张本地缓存图片做 CSS 变换；文字、定位圈、逗号和蓝点分层。手势最多每 50ms 合并一次小型界面更新，静止时不持续刷新动画；未做实际帧率测量。 |
| 位置 | 复用现有 `location.start()` / `subscribe()` / `peek()`。首次取得校园内位置时跟随定位；过期位置降低蓝点透明度。定位圈代表报告的误差，不是解锁范围。 |
| 留言 | 复用附近结果和原有聚合，地点坐标不移动。查看整校不会扩大云端查询范围或绕开距离分层；地图上不植入示意用户内容。 |
| 到场规则 | 原有精度、位置时效与服务端校验保持不变。底图的艺术细节和手动浏览位置均不参与发布、点赞或回复权限判断。 |

蓝点在留言标记上方，地图图层整体在卡片与导航下方。这里沿用轻量图片层，避免原生画布层遮住界面，也不为每次拖动导出新图片。

建筑高度、道路绘制宽度、屋顶排线、灯光、球场标线和树木位置均为艺术示意，不能用作建筑入口或导航依据。部分建筑轮廓较粗，名称也与官方图存在差异。坐标转换解决坐标体系衔接，不会改善源数据精度；`fieldVerified` 仍为 false。

## 文件与重建

- `miniprogram/utils/campus-map.js`：投影、相机、随动、缩放与轻量显示数据。
- `miniprogram/data/campus.js`：生成的 GCJ-02 原点、边界、标签及图层元数据。
- `miniprogram/assets/campus/uibe-night.jpg`：客户端实际使用的底图资源。
- `docs/campus/uibe/data/campus-render.json`：保留源对象 ID 的构建用派生几何。
- `full-campus-preview.html`：与小程序共用相机模块的本地预览，位置来自公开道路上的模拟样本，不读取 GPS、不连接云端。

```sh
node scripts/prepare-campus-map.cjs
python3 scripts/render-campus-map.py
node scripts/build-campus-gps-preview.cjs
```

Python 绘图需 Pillow。源模板在 `scripts/templates/campus-gps-preview.html`；生成预览内嵌同一份客户端相机代码，不另外维护一套跟随算法。客户端代码和资源原始文件合计约 1.56 MB；这不是开发者工具正式打包尺寸。

## 实际验证状态

- JavaScript 语法与变更空白检查完成；生成资源已打开检查。
- 在微信开发者工具 2.02.2609231 RC、基础库 3.17.4 中打开本仓库与当前 AppID，编译并实际显示了校园地图与原有界面。定位使用工具默认模拟结果，报告精度较弱，界面保留整校概览；未把它当作真机位置。
- 使用同一客户端相机模块的浏览器预览，人工检查整校概览、按钮缩放、公开道路模拟位置变化时的随动、拖动暂停随动及返回概览。截图为 `full-campus-overview.png`、`full-campus-follow.png`，均为浏览器模拟数据画面。
- 真机 GPS 随动、校园现场对齐误差、iOS/Android 手势表现、实际帧率及真实多用户留言仍待验证。没有宣称已完成这些步骤。
- 本次只改客户端及素材；云函数、数据权限和已部署环境没有升级。可重新编译并手机预览，不需要重新部署云开发。

## 采点与补绘的下一步

先在校园内选 3—5 个开阔路口，用真机检查蓝点相对道路的偏差并记录精度和时间；按 `control-points.csv` 收集同一地面点，保留独立检查点。再补核东北片区、建筑群细分和入口。不要通过拖动蓝点或修改现场门槛来掩盖底图误差。
