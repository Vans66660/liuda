# 后端接口约定

客户端已启用云环境 `cloud1-d3gkowfe36d11fc12`。`liudaApi`、九个集合、五个索引和数据访问权限已配置，两项服务端凭据已保存且试点已开启，实际调用仍未确认。环境配置和账号要求见 `cloud-setup.md`，不能将本机演示成功当作云端发布。

## 当前联机接口

统一通过 `wx.cloud.callFunction` 调用 `liudaApi`，请求包含 `action`，位置请求同时包含 `position`。响应为 `{ ok, data, serverTime }` 或 `{ ok:false, error:{ code,message }, serverTime }`。

| action | 职责 |
| --- | --- |
| join / status | 邀请加入、检查试用资格；内部身份来自微信调用上下文 |
| nearby | 地理索引查询 350 米内最近 50 条，服务端决定 dot / preview / full |
| thread | 先校验对话参与资格；参与者无需定位可读原文/配图/回复，未参与者按位置分层；不返回内部身份 |
| presence | 发放绑定内部身份、操作和目标的一次性凭证，30 秒失效 |
| post / comment / like | 重新检查位置、凭证、频率；事务消费凭证与写入，按请求编号去重 |
| continueComment | 已参与者在同一条对话继续回复；事务复核资格、留言状态、频率及幂等，文字仍需审核 |
| uploadPhoto / photo | 上传仍需现场；读取允许现场用户或该对话参与者，不下发文件 ID 或公开地址 |
| mine / conversations / activity / inbox | 本人、已参与对话和近期回应概要；inbox 聚合三个列表，完整内容单独鉴权读取 |
| delete | 仅作者可逻辑删除，不要求到场；停止后续公开读取与回复 |

位置为 GCJ-02，包含坐标、时间戳和设备报告精度。当前位置最大时效 15 秒、精度不超过 30 米、距离加误差不超过 50 米才允许现场操作。现场写入包含 `requestId` 和 `ticket`；续聊写入只需 `requestId`，由服务端在事务中复核 `liuda_threads` 的当前账号参与资格；正文变化必须使用新的请求编号。两条评论路径共用幂等命名空间，跨现场/续聊重试不重复写入。

`status` / `join` 返回 `protocol:2`。新客户端遇到旧协议明确提示更新云函数。`thread` / `photo` 对参与者接受无 `position` 请求；未参与者缺位置返回 `LOCATION_REQUIRED`。返回的 `participated`、`accessMode`、`canReply` 与 `canLike` 均由服务端生成，不能作为下一次请求的授权凭据。`canInteract` 继续表示当前现场权限，不能用参与资格在远处创建新留话。参与者内容快照有效期 60 秒，未参与者保持原 12/15 秒限制。

文字审核通过后才写入。照片经压缩、格式检查和同步图片审核后暂存，发布时绑定到留话；接口不可调用时拒绝图片。图片暂存及逻辑删除的文件清理尚需管理员处理。

数据库和存储禁止客户端直读直写，只允许云函数处理。公开匿名不意味着后台无内部身份；当前普通设备位置证据不能证明定位未被伪造。

## 基本原则

- 服务器从受信任登录流程获取内部身份，不采纳请求体中的任意作者 ID。
- 位置数据包含坐标系、时间和精度。地图展示与距离计算必须明确坐标系并统一转换。
- 设备位置与相机信息均来自客户端，只能作为分层到场判断的证据，不能保证绝对真实。
- 新发帖、首次评论、点赞及非参与者读取重新校验位置新鲜度、精度和范围；参与后续聊使用独立的服务端对话成员记录，不复用到场凭证。
- 公开与私聊身份不使用可跨场景公开关联的 ID。
- 内容、图片和评论按读取层次分开返回，生产客户端不得包含演示全文数据。
- 图片使用受控存储，签名读取权限与地点读取权限一致。普通公开下载地址不适合隐藏原图。
- 所有真实发布在完成内容治理与权限方案之前保持关闭。

## 会话与付费状态

建议使用显式状态：`pending → active → destroyed`，待同意申请另可进入 `declined`／`cancelled`。`destroyed` 为终态，旧消息、重试请求和离线同步不得让会话复活。

同意、扣权益和建会话应具备一次性执行保障。支付订单、权益账本和消息内容分开保存。以服务端验签和查单确定支付结果，不能只信客户端“支付成功”。

## 销毁流程

1. 校验双方之一的权限，将会话写入销毁终态，立即停止服务端读写。
2. 删除活动消息与图片，撤销仍可用的下载访问，触发缓存清理。
3. 向在线设备发送销毁事件；离线设备下次同步时先处理销毁状态，再呈现会话。
4. 将客户端缓存、备份与第三方消息服务纳入删除策略，并核实供应商接口的实际语义。
5. 付款账本和必要记录独立处理，遵循预先明确的留存规则。

无法控制对方截图、录屏、修改客户端或自行导出的副本。没有联网的设备不能保证即时执行远程删除。
