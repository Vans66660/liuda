# 核心机制：到场开启交流，离场也可继续

确定及实现日期：2026-10-21。

## 产品规则

用户旅行、毕业或搬家后，仍可知道自己留下的话得到了什么回应。首次参与一个具体地点的具体对话需要到场；这次交流可以在离场后继续。

| 行为 | 规则 |
| --- | --- |
| 发布一条新留话 | 新鲜 GPS、精度、到场凭证和审核全部通过后发布 |
| 第一次在别人的留话下接话 | 到场验证和审核通过，成功写入后获得本条对话资格 |
| 浏览、点赞、路过某地点 | 不获得持续参与资格 |
| 读取自己参与过的对话 | 离场可读原文、配图及后续回复；不要求重新授权或获取 GPS |
| 继续回复参与过的对话 | 不要求位置，仍需当前账号有效、对话有效、审核通过、限频和幂等校验 |
| 同地点的另一条留话 | 重新按未参与者规则判断，不共享资格 |
| 新发帖、点赞、首次私聊申请 | 仍按现场规则；私聊功能尚未实现 |
| 留话已删除，或账号试用资格已暂停 | 停止服务端读取与回复 |

这是公开对话的延续，不是私聊权益，不收费。它不提供他人的公开个人主页或跨地点发言列表。

## 用户入口

- 消息页默认展示“我参与的”，包含本人留话与现场接过话的对话；另有“我留下的”“回应”。
- 对话页显示“已参与这条对话 · 离场也可继续”，回复按钮显示“继续接话”。
- 续聊只标记“续聊”，不公开参与者当前坐标，也不声称某人此刻一定身处现场。
- 已参与者打开对话、读取配图和发送续聊均不主动获取新 GPS。本人主动点击“我在现场，更新位置”时才为现场操作启动定位。
- 对未参与者，定位仍用于距离分层与首次接话资格。
- 回应是站内轮询显示的近期对话活动，不是已实现的微信订阅通知或推送；也不是逐条未读计数。

## 服务端资格

新增私有集合 `liuda_threads`，文档 ID 为内部用户身份与留言 ID 的哈希，字段为 `owner`、`postId`、`name`、`state`、`joinedAt`、`entry`。客户端不能直读直写。

作者发帖、首次现场回复与资格写入在同一事务中提交，失败不会留下资格。离场续聊的事务只承认现有成员记录，不会凭客户端的 `participated`、坐标、场景 ID、浏览或点赞创建资格。

旧作者、旧回复者在第一次读取对应对话时，服务端根据原文作者身份、旧的现场回复者数组或本人实际评论记录补建资格。补认事务会再次核对原始记录与留言状态。历史记录不存在、属于其他人或仅有续聊标记时，不能凭此获得新资格。

作者仍可随时逻辑删除整条留话，所有后续接口检查 `state=active`。资格保存在原留言维度，不可复用于同一 `sceneId` 的其他留言。

参与者快照有效 60 秒；客户端到期收起内容并要求刷新，页面隐藏时清理图文内存。正常轮询重新校验资格与留言状态。不承诺收回已经看过、截图或另存的内容。

## 接口与兼容

- `status` / `join` 返回 `protocol:2`。
- `thread` / `photo` 先判断参与资格；参与者可不传位置，未参与者缺少位置返回 `LOCATION_REQUIRED`。
- 原 `comment` 继续要求现场位置和一次性凭证；新增 `continueComment` 不接受位置作为授权，只接受真实成员资格。
- 两条评论路径共用 `comment` 幂等空间及相同正文哈希，因网络重试从现场切换到续聊时不重复写入。
- 新增 `inbox` 返回本人、已参与对话和近期回应三个元数据列表，页面一次请求聚合，避免分别重复拉取。
- 回应页扩展到曾现场回复的参与者。每段对话汇总最近一条活动，最多 20 段；本人续聊不制造“别人回应了你”的新事件。
- 原有演示数据可根据本人作者或 `mine` 评论识别参与资格，新演示回复也会保存资格。
- 对话列表当前最多 50 段；升级过渡查询本人最近 50 条原文、最近 100 条评论和最近 50 条成员记录。更老的已知留言仍可凭具体 ID 在打开时核验补认，历史列表的完整分页留待后续扩展。
- 新客户端检测旧协议时明确提示部署新版云函数，不把后台未升级误报为手机定位权限失败。

## 云端升级顺序

1. 在现有环境 `cloud1-d3gkowfe36d11fc12` 创建集合 `liuda_threads`，数据权限设置为“所有用户不可读写”：`{"read":false,"write":false}`。
2. 新建以下三个非唯一索引，已有的五个索引保持不变：

| 集合 | 名称 | 字段顺序 |
| --- | --- | --- |
| `liuda_threads` | `member_threads` | `owner` 升序、`state` 升序、`joinedAt` 降序 |
| `liuda_comments` | `member_comments` | `owner` 升序、`state` 升序、`createdAt` 降序 |
| `liuda_comments` | `thread_member` | `postId` 升序、`owner` 升序、`state` 升序 |

3. 索引就绪后，上传并部署新版 `liudaApi`，选择“云端安装依赖”。保留既有 AppID、匿名密钥、邀请码和试点开关。
4. 完整编译客户端，重新预览并扫码。GitHub 合并或推送源码不等于执行了上述升级。

新客户端需与新后端配套；旧客户端仍会按旧逻辑要求位置，不能据旧预览判断续聊失败。
