## 使用场景说明草稿

### getLocation：获取当前位置

留答提供与实际地点绑定的留话与现场回复。用户从“附近”页面主动切换到“真实定位 · 联机留话”或点击“开启定位”，阅读并同意隐私保护指引及位置授权后，程序获取当前位置，用于展示附近留言点、计算用户与留言点的距离，并在发帖或回复时判断是否到场。位置过期、精度不足或超出范围时限制现场互动。用户公开界面不展示账号的实时位置或行走轨迹。

### startLocationUpdate / onLocationChange：前台位置更新

用户在“附近”地图页开启真实定位后，步行会改变与留言点的距离。程序通过前台位置更新刷新地图中心、距离标签及留言可读范围，减少地图和实际位置不同步。现场发布页与对话页也使用最新位置判断是否到场。离开这些页面或小程序进入后台时停止持续定位，不申请后台持续定位。

`startLocationUpdate` 用于启动前台更新；`onLocationChange` 用于接收该更新的回调。申请时应分别指明用途，不能只写“需要定位”或“用于社交”。

## 需要配套的实际材料

| 画面 | 要让审核人员看到的内容 | 注意 |
|---|---|---|
| 入口 | 首页“真实定位 · 联机留话”或“开启定位” | 显示完整页面与产品名称 |
| 隐私授权 | 用途说明、隐私指引入口、官方同意按钮 | 由用户自行操作；隐去无关个人信息 |
| 附近地图 | 本人位置、留言点、距离标签、回到当前位置按钮 | 必须区分真实定位与演示数据 |
| 距离变化 | 行走后用户位置、距离及可读范围随之变化 | 只有实际运行后才可声称真实效果 |
| 现场互动 | 到场时可留话/回复，离场或精度不足时受限 | 使用本人可公开的素材，不暴露旁人信息 |

建议录制一段按上述顺序的完整操作视频，并按申请表实际要求提供截图、版本入口或可访问材料。若接口未开放导致无法展示真实定位，应在材料中说明这一限制，并向平台确认可接受的演示方式；不要用模拟步行冒充真机定位。

## 申请顺序建议

先核对主体、类目与单次定位准入。符合实际业务时，优先把 `getLocation` 的用途与页面材料说明清楚；若单次定位获准，再评估是否先以手动更新位置实现试用，并单独补充持续定位的必要性。三个接口全部未获准时，不能承诺通过代码改动即可接通手机定位。

参考：[腾讯云官方定位权限配置说明](https://docs.cloudbase.net/lowcode/components/wedaUI/src/docs/compsdocs/form/WdLocation)、[微信官方接口类型声明中的准入说明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。
