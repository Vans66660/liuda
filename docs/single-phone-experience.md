# 一台手机的体验完善

> 初代微信小程序历史文档。当前 App 开发请看 [仓库首页](../README.md)。

更新：2026-10-19。以下为本轮客户端实现记录，不代表新增功能已经真机确认。

## 地图浏览

- 新增“附近 N 条”入口，可打开附近留话选择菜单；卡片支持切换下一条，关闭后仍可重新找到内容。
- 真实地图新增缩放、刷新和回到当前位置操作，显示是否处于跟随状态。手动拖动地图后可重新回到跟随。
- 当前选中的地图气泡使用浅色突出，本人留话带“我留下的”提示。
- 区分首次加载、未加入试用、网络刷新失败及附近没有内容；网络失败提供重试，不再一律跳转邀请码页。
- 卡片正文最大高度随窗口调整，以便保留关闭、回复和下一条等操作。
- 记住上次选择的演示/真实模式和地图/空间视图。只保存这些界面偏好，不把邀请码或定位写入偏好文件。

## 现场留话

- 默认允许在当前位置新建地点，填写精细位置名称；这一步不依赖附近地点查询成功。已有地点通过另一个菜单选项选取，仍只允许使用到场范围内的地点。
- 位置状态可刷新；缺少有效位置、内容或地点名称时禁用提交。对已有地点的距离与位置时效继续参与判断。
- 本人未提交的文字、地点选择与照片临时路径按演示/真实模式分别保存在运行内存。切换标签可继续填写；关闭进程后不保证保留。清空草稿前需用户确认。
- 支持现场照片预览和移除。真实照片仍只能通过相机拍摄，发布仍走原有位置检查与审核流程。
- 提交显示当前位置确认、照片处理和提交等进度；失败保留草稿。网络结果不明确时保留原请求标识供同内容重试，避免把网络超时误报为一定未发布。
- 服务端返回成功回执后展示“留在这里了”，可查看本人留话、回到地图或继续留话。成功页不展示离场后仍可绕过权限读取的全文缓存。

## 本人留话与对话

- “路过的痕迹”默认打开“我留下的”，回应单独放在另一个标签中；新增发布时间、刷新和下拉刷新。
- 回应读取失败时，本人留话列表仍可独立刷新。真实模式的离场列表仍只显示地点、时间和回复数量，不增加全文。
- 对话页可回到附近地图、刷新或重新获取位置；定位失败后的重试会重新启动定位。
- 本人删除后清理当前对话状态，并通知地图移除相应缓存。演示模式缺失内容采用明确的不存在状态。
- 现场给自己的留话回复，可以在该条对话中查看；服务端不会生成“其他人回应了你”的通知。跨账号同步继续保持待验证。

## 建议体验路径

1. 完整编译并重新扫码预览，选择演示街区或已加入的真实定位模式。
2. 打开附近留话菜单，关闭/重新打开卡片，切换下一条；真实地图可缩放、刷新及回到自己位置。
3. 点击“留下”，填写具体地点名称和一句话；切到附近再返回，查看草稿是否保留。
4. 提交后从成功页打开自己的留话，现场接一句，再回到地图或“我留下的”。
5. 真实模式的发布、审核、照片和离场限制仍以实际服务端结果为准；定位正常不代表这些环节已全部确认。

## 2026-10-20：输入延迟与文字回跳修正

用户反馈手机输入文字卡顿，文字短暂消失后重新出现。代码中存在输入事件逐字 `setData` 回写同一输入框 `value`，并追加多次表单状态更新的路径。这是与现象相符的可疑原因，尚未通过真机性能记录确认全部耗时。

- 留话正文、地点名称和回复改为原生输入框持有输入内容；事件只更新逻辑值、字数和按钮状态，不把逐字内容往回写。
- 恢复草稿、选择已有地点、主动清空和提交成功时，通过带新标识的输入节点设置内容。忽略旧节点迟到的输入/失焦事件，防止清空后旧文字再次进入草稿。
- 失焦事件补收最终输入值；原有草稿保存与发布仍读取最新逻辑值。地点名称普通输入不再重复刷新整组定位状态，状态未变化时不重复调用 `setData`。
- 定位时效与到场权限检查继续运行。没有为输入流畅而暂停权限检查。
