# 逗号热度与地图聚合

> 初代微信小程序历史文档。当前 App 开发请看 [仓库首页](../README.md)。

更新：2026-10-20。客户端与云函数源代码已修改；云端新版本未部署，真机效果未确认。

## 界面

- 地图不再给每条留言常驻一条长地点标签，改用逗号标记。
- 腾讯底图的 POI 地点标识保持开启（`enable-poi=true`），方便辨认周边建筑和场所。此前关闭了该开关，用户真机反馈底图缺少地点文字后恢复。具体标注的名称、密度和道路文字由腾讯底图与缩放级别决定；恢复配置后的手机结果尚未确认。底图标识与留话卡片的地点名独立。
- 普通、有回应、热门采用 32 / 39 / 46 px 的可见图形；底色分别为深灰、更深灰、近黑。选中时加白色描边。图形边缘留白不计入可见尺寸。
- 多条留言显示数字，超过 9 条显示 `9+`，底部列表显示真实条数。所有标记使用预生成的本地 PNG，不在定位回调中生成图片。
- 同一 `sceneId` 的留言共享入口。不同地点按当前缩放级别的屏幕投影聚合；只聚合显示，不修改留言坐标、地点 ID 或到场条件。
- 点击跨地点的聚合点，会先增加两级缩放。如果能拆开则展示独立标记，仍重叠则打开列表；同一地点的多条留言直接打开列表。
- 数字表示留言数量，聚合点的热度取其中最高一条，避免单纯堆量撑大气泡。
- 列表支持推荐/最新。选择一条后进入原有底部卡片；卡片可返回“这组 N 条”。“附近 N 条”也使用同一个可滚动列表，不再只列前六条。
- 3D 示意街区同样使用逗号和投影聚合，去掉原先为错开标签而设置的纵向偏移。3D 仍是虚构场景，不是真实建筑模型。

## 热度初始规则

可调初始参数：`(点赞数 + 3 × 不同回复者数量) × 0.5^(距最近有效互动的天数 / 7)`。小于 5 为普通，5 至不足 20 为有回应，20 及以上为热门。这是热度提示，不代表内容质量已经经过判定。

- 点赞沿用服务端每人每条唯一状态。
- 同一个人多次回复只计一个回复者；作者回复自己不增加回复热度。新增不同回复者时更新互动时间，重复回复、点赞反复开关不会刷新该时间。
- 服务端私有文章记录中保存去重身份数组 `replyParticipantIds`。客户端只获得数量 `replyParticipantCount` 与 `lastEngagedAt`，不返回身份数组。
- 老留言未回填历史回复者，历史回复数不直接换算成热度；更新后从新增的不同回复者开始累计。老服务端未提供新字段时，客户端保守只按点赞计算。
- 推荐列表的第 1 位及此后每 4 位，为 24 小时内的普通新留言保留位置；其余按热度排序。最新列表按创建时间排序。仅在本次附近查询结果中排序，不能保证进入服务端最近 50 条之外的留言。
- 本机演示从示例回复者名字去重，排除 `mine` 回复。新增本机示例仅用于看聚合和三级样式，不上传真实环境。

## 距离和数据边界

列表正文只使用已经过当前距离、精度、时效处理的 `displayText`，不从 `text` 字段恢复全文；定时与定位更新继续收紧读取权限。聚合中心锚定一个真实成员点，仅用于展示；发布与回复仍针对原来的具体地点和留言。

新建地点不能仅凭经纬度相近视为同一个物理场景；目前没有楼层识别。

## 查看效果

1. 完整编译，重新预览扫码。通过左上位置入口选择“演示街区”，关闭初始卡片可查看逗号；点带 `3` 的台阶标记打开三条留言列表。演示还包含普通和中等热度点，视角或投影可能将相近点临时聚合。
2. 真实模式重新编译即可看到聚合、标记和按现有点赞计算的热度。若要启用不同回复者计数，在开发者工具右键 `cloudfunctions/liudaApi`，选择“上传并部署：云端安装依赖”。保留已有云环境变量、数据库/存储权限与索引；本次不需要新建集合或索引。
3. [界面示意图](previews/map-heat-and-clusters.png) 为代码生成的设计说明，不是手机截图或真实互动数据。

图标源生成器为 `scripts/build-map-pins.cjs`，在 Node 的模块搜索路径可加载 `sharp` 时运行。

本轮仅进行了变更 JavaScript 的语法解析与生成图形的目视检查，没有运行自动化/功能测试、发布真实留言、上传手机预览或部署云函数。
